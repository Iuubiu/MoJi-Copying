# 墨迹 · 小说抄写工作台

> 抄书不是抄袭，是把别人的手艺拆开、长在自己手上。

`v0.1` · 一个为「抄书特训」做的本地工具：左边原文、右边抄写区，逐字对照、自动校对，
每天抄了多少字、练了多久，都替你记着。数据只存在你自己的机器上，不联网、不上传。

## 为什么会有这个工具

起点编辑星河在直播里讲过一套很实在的抄书方法论，大意是：

> 抄书不是让你去抄袭剽窃别人的故事剧情，而是通过各种技巧与锻炼，
> 让作者迅速入行，或者让实力稳步提高。

他把抄书分成三段。

### 萌新阶段：先看自己缺什么

| 你的短板 | 抄什么 | 练的是什么 |
| --- | --- | --- |
| 文笔差，但思路好、对市场有感觉 | 新书榜 / 新书畅销榜里 **100 万字以内、非大神白金作者**的题材对标书，对准免费章节，分屏照抄，**每天 4000–6000 字** | 文笔。好词句单独存一个文档；同时想：他为什么这样写剧情、节奏怎么安排、人设怎么塑造、哪里点到为止 |
| 文笔不错，题材思路跟不上 | **新书榜前 200** 的简介、书名、开头三章，每天同样四到六千字 | 框架，而不是句子。想他们的题材选择、人设标签、前期剧情安排；再往后拆第一个大高潮如何平稳落地、闭环的同时引出后续 |
| 两样都差 | 两者结合，**每天一万字以上** | 手感与耐心。在枯燥的抄写里体会代入感、沉浸感、期待感、情绪反馈这些最基本的要素 |

### 进阶阶段：已经能靠网文月入小几千

依然要抄。摘抄一些书的开头或高潮段落，让自己对文字的嗅觉保持敏感；
哪怕只是拆书看书，抄几段词句也很有必要 —— 每个阶段都有新的短板，停下来的那天就开始退步。

### 老手阶段：月入十万以上

反而最用心。会说话的肘子每本书的进步都肉眼可见，市场上每本爆款书都能举例子娓娓道来；
陈东会把本章说的热梗、当下的热门新闻立刻化用进章节 —— 他们一直在拆市场、拆本章说，从不封闭创作。

---

这套方法的核心动作只有一个：**对着好文本，一个字一个字地写下去，边写边想他为什么这么写。**

这个工具就是为这个动作做的。它不替你思考，不做任何"AI 改写"，只做三件事：
把原文摆正、把你写的每个字和原文对齐、把你练了多少记下来。

## 抄书的时候，它怎么帮你

| 特训里要做的事 | 工具里对应的功能 |
| --- | --- |
| 分屏对照、照着抄 | 抄写工作台：左原文、右抄写区，两栏**同宽、同起点、逐行对齐**；写到最后一行立即整行下滚，抄写区底部常年空出一行，方便对照另一侧原文 |
| 一眼看出抄错了哪个字 | 逐字校对：写对的字是黑的、写错的字是红的；「校对清单」列出每一处偏差，点一下光标就跳到那个字 |
| 抄完一段，回看自己漏在哪 | 光标所在句会单独显示；原文栏与抄写栏按同一行坐标双向同步滚动 |
| 摘抄好词句 | 全文搜索能定位到原文的任意位置并高亮；选中文字即反色。整理交给你的笔记软件，工具只保证你抄得到 |
| 每天四千到一万字的量 | 侧栏实时显示已抄字数、本次时长、平均速度、完成度与正确率；左侧「今日小目标」盯着当天的量 |
| 三个月不断 | 统计页：连续天数、历史最长连续、最近 7 天柱状图、与上一周期的对比 |
| 按章拆书 | 章节目录支持逐章重置 / 删除；导入时自动识别「第 X 章」「序章」「Chapter 1」等标题切分章节，超大章节自动再拆成可消化的段落 |
| 各种 TXT 都能用 | 自动识别 UTF-8 / UTF-16 / GB18030-GBK 编码，识别不准时可在左侧手动切换 |

## 快速开始

```bash
python -m server --open                 # 起服务并打开浏览器（默认 http://127.0.0.1:47299）
python -m server --port 8000            # 换个端口
python -m server --db ./practice.sqlite3  # 把库放到指定位置
```

只需要 Python 3.10+ 与标准库，**不需要安装任何第三方依赖**。

Windows 用户也可以用桌面版（独立窗口，不依赖浏览器）：见 [`desktop/使用说明.md`](desktop/使用说明.md)。

## 上手三步

1. 点左侧「导入新小说」，选一个 `.txt` / `.md` / `.text`（对标书的正文，或你自己整理好的拆书笔记）。
2. 在章节目录里选一章，点「开始抄写」，直接在右侧敲 —— 写错的字会变红。
3. 抄完一段点「校对清单」回看偏差；今天的字数与时长会自动记下来。

快捷键：`Tab` 下一章 · `Ctrl/Cmd + Enter` 完成本章 · `Esc` 退出专注模式。

## 架构

前后端分离，两端都刻意保持"没有魔法"：

```
web/                 前端：原生 HTML / CSS / JavaScript，无框架、无构建步骤
  index.html
  app.js             渲染 / 交互 / 会话计时与落库
  api.js             后端 REST 客户端 —— 前后端之间唯一的通道
  stats.js           统计纯计算层（Node 侧有 82 项回归测试）
  encoding.js        文本编码探测（同）
server/              后端：Python 标准库 + SQLite，零第三方依赖
  store.py           SQLite 持久层：六张表 + daily 物化视图
  api.py             REST 路由
  http_app.py        HTTP 服务：静态资源与 API 同端口
  paths.py           数据目录 / 前端目录约定
  tests/             后端回归测试（unittest）
desktop/             桌面外壳（pywebview + WebView2）
verify/              端到端回归（CDP 驱动真实浏览器）
```

后端只做持久化，不做业务计算：统计、校对、完成度都由前端的纯函数负责
（它们有 82 项 Node 回归测试盯着，复制一份到 Python 会立刻失去这层保护）。
`daily` 是 `sessions` 的物化视图，由后端在同一个事务里重算 —— 统计口径只有一个来源。

前端与后端同源，默认不需要处理跨域。想把前端单独部署（前端 5173、后端 8000），
在 `web/index.html` 里写上后端地址即可：

```html
<meta name="moji-api" content="http://127.0.0.1:8000" />
```

后端只接受本机来源（`127.0.0.1` / `localhost`），也只对本机来源回 CORS 头 ——
你的抄写记录不会被别的网页读走。

## 数据存在哪

```
Windows       %LOCALAPPDATA%\MoJi\moji.sqlite3
Linux / macOS ~/.local/share/moji/moji.sqlite3
```

一个 SQLite 文件就是全部数据。桌面版与命令行版本共用这一份；
用 `MOJI_DATA_DIR` 可以整体挪走。备份就是复制这个文件，或者用设置里的「导出备份」。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 服务与数据库状态 |
| GET | `/api/bootstrap` | 一次性取全量：books / progress / sessions / daily / settings |
| GET | `/api/export` | 导出完整备份（JSON） |
| POST | `/api/import?mode=merge\|overwrite` | 导入备份 |
| PUT | `/api/books/{id}` | 整本书写入（元信息 + 章节正文 + 每章进度，同事务） |
| DELETE | `/api/books/{id}` | 删除书及其章节、进度 |
| PUT | `/api/books/{id}/progress/{index}` | 单章进度（打字时高频调用） |
| PUT | `/api/sessions/{id}` | 写入／覆盖一次练习会话，返回重算后的当日汇总 |
| DELETE | `/api/sessions` | 清空练习记录 |
| PUT | `/api/settings/{key}` | 写一条设置 |

## 测试

```bash
# 后端：持久层 + HTTP 层（36 项）
python -m unittest discover -s server/tests -t .

# 前端纯计算层
node verify/test-stats.js          # 统计 82 项
node verify/test-encoding.js       # 编码探测 21 项

# 端到端（CDP 驱动真实浏览器；先起后端）
python -m server --port 41777
node verify/cdp-attach.js <debugPort> verify/checks-features.js            # 界面与数据层 64 项
node verify/cdp-attach.js <debugPort> verify/checks-session-persistence.js # 会话落库与统计口径 9 项
node verify/cdp-attach.js <debugPort> verify/checks-migration.js           # 数据搬迁 10 项
```

写这个工具时踩过的坑都留了注释：为什么落库要每 5 秒一次、为什么要留退出快照、
为什么速度的分子分母必须同口径 —— 这些在界面上的表现只是"数字不太对"，
靠肉眼很难发现，所以每一条都配了回归检查。
